## 1. 先分清“题源”和“基线”

## 2. 每道题具体补了什么

逐题文件保留英文实际问题，不以中文改写替代原始测试输入。主要条目包括：

1. 稳定 ID、类别、开发/held-out/派生/历史标记。
2. 题目原文，以及公开数据集、源论文、冻结题集或测试源文件位置。
3. 公开参考答案、论文原句/Child ID、人工段落归属，或工程断言等验收条件。
4. 各比较方案的实际结果；有逐题 token 时使用正确账本字段。Agent 的 `tokens` 是任务消耗，`usage` 在该汇总里是评审消耗，二者没有混用。
5. 已保存的逐题评审理由；对于记忆还展开两组实际回答。长篇 Agent 回答与 RAG 上下文通过原始证据链接核查。
6. 有日志支持的故障定位，以及该结果支持/不支持什么能力。

“为什么”必须区分三种证据：**可观察事实**，例如目标论文没进上下文；**评审判断**，例如答案漏了某个参考事实；**机制猜测**，例如可能由重排偏好造成。前两者有直接记录，第三种不能在没有控制变量实验时写成定论。若原始记录没有逐题根因文字，本附录明确说明，不根据一个低分编造原因。

## 3. 面试时值得讲清楚的具体例子

### 例一：q01，不是模型不知道答案，而是不同链路拿到了不同证据

实际问题：

> What processor, clock speed, memory capacity, and operating system were used to run the Plato experiments?

参考答案为 i7-4770、3.6 GHz、16 GB、Ubuntu 14.04.1。legacy 的上下文来自其他系统，正确地拒绝了猜测，因此答案相关性和参考事实召回为 0，忠实性为 NA；NA 不能填成 0 或 1。anchored 拿到精确实验环境原句，四个事实都回答，相关性、参考事实召回与忠实性均为 1。

但该题独立检索消融中的 full，Recall@5 和 ParentHit@10 均为 0。二者不矛盾：**独立检索 full 与经过查询规划、证据锚定的 anchored 生成不是同一条输入路径**。不能把这一次改善单独归因于 rerank，更不能用生成成功掩盖检索消融中的漏检。

这说明调试首先要检查实际进入生成器的证据，而不是先改回答提示词。[逐题记录](question-analysis-v20261110/01_RAG最终65题逐题分析.md)

### 例二：q50，忠实性 1.0 仍然只覆盖 0.4 的参考事实

实际问题：

> How do SPERR and SZ differ in the mechanisms they use to keep reconstructed data within user-required error bounds?

anchored 对 wavelet/SPECK、outlier correction、量化等说法有依据，忠实性 1.0；但参考事实召回仅 0.4。原始评审明确指出，漏掉了 **SZ 使用此前解压值而非原始值进行预测** 这一关键机制，也未明确 SPERR 同时编码异常点位置与修正值。

因此“说出的都可支持”和“把需要的都说完”是两件事。这类遗漏会影响写综述和方法复现，不能说完全没有影响；个人工具的可接受用法是追问缺项并回读原文，而非直接采信自动完整总结。[逐题记录](question-analysis-v20261110/01_RAG最终65题逐题分析.md)

### 例三：q56，部分拒答是合理行为，但仍然没完成跨篇问题

实际问题比较 PrunedDTW 的矩阵剪枝与 LB_Webb_Enhanced 的构造。两组都能解释 PrunedDTW，但没有拿到定义后者所需的 path-to-band 替换证据，因此参考事实召回 0.5，并明确部分拒答。

不编造缺失一半是正确边界；没有完成对比仍是完整性不足，不能因为忠实性 1.0 就宣布这道题完全成功。它暴露的是跨篇比较中的证据覆盖问题。[逐题记录](question-analysis-v20261110/01_RAG最终65题逐题分析.md)

### 例四：fact-sz，为什么引用存在还会判失败

实际任务要求从本地文献解释 SZ 的绝对误差控制，并禁止推广到所有时序任务。新 LangGraph 回答的预测/量化/编码主干有据，但引用的 SDRBench 返回片段仅含 “be extended”，不足以支持附加的 PSNR 模式和 2.1 版本细节。

该题 success=false、supported=false。它说明宿主能验证引用 ID 存在，却不能仅靠 ID 验证语义蕴含；一个引用来源真实，仍可能被用于支撑它没有说过的细节。保留失败比重跑到高分更有解释价值。[Agent 逐题对照](question-analysis-v20261110/05_Agent24题与32路由问题.md)

### 例五：06f04340，记住了部分偏好，仍不能算完整个性化

实际问题：

> What should I serve for dinner this weekend with my homegrown ingredients?

新策略建议用了 basil/mint，却漏掉参考要求中的自种 cherry tomatoes，银标判错。这不是论文知识不足，而是用户偏好/历史事实选择不完整。对应科研使用，系统可能保留“做压缩”却遗漏“设备只有多少内存”，所以关键约束需要明确写入 State，而非全交给模糊偏好召回。[公开单会话逐题记录](question-analysis-v20261110/03_单会话156题及36派生案例.md)

### 例六：25e5aa4f / 4baee567，保守回答也可能被参考答案判错

前者问计算机学士在哪所大学完成，参考是 UCLA，候选表示不能确定；后者问 Chiefs/Jaguars 在 Arrowhead 的交锋次数，候选提到 12 却拒绝确认，并加了参考没有要求的限定。两题在银标中判错。

这提示评测要兼顾“参考事实匹配”和“来源是谁、是否只是助手历史建议”的解释差异。不能因为模型保守就改成正确，也不能为了提高分数强迫系统确认不可靠事实；本附录保留实际答案与 judge 理由，作为未来人工复核对象。[逐题记录](question-analysis-v20261110/03_单会话156题及36派生案例.md)

### 例七：结构 8 题，为什么找到了论文还决定不迁移

结构候选的论文级 Recall 可能仍高，但前三条“直接能回答的证据”从 6/8 降到 3/8；例如 decimal_xor 的原方案前三条包含直接证据，候选只剩背景支持。这里考的是证据粒度，不是标题是否相关。

因此没有凭直觉强推结构 Child，而是保留胜出页级/词窗 Child，并让章节感知承担证据归组和父级扩展。结论限定为“当时实现未胜出”，不是“结构切分永远不好”。[结构逐题等级](question-analysis-v20261110/02_RAG历史结构消融与增量问题.md)

### 例八：真实 Skills 验收“通过”，为何科研回答仍 partial

现场测试实际出现 discover/load/invoke 三类事件，证明技能不是文档里的摆设；但最终答案在复核中保留未确认的 hash/schema 与科学证据缺口，状态为 partial。

所以三事件检查通过仅是能力接线验收，不能包装为完整科研任务通过。类似地，用户明确要求执行两节点 DAG 的成功，不是一般开放任务“自主规划成功率 100%”。[现场原始问题与回答](question-analysis-v20261110/11_现场问题与性能用例说明.md)

## 4. 历史结果与证据不足之处

旧 SQLite 时代 12 个 ViT/PEFT 问题的 Fusion 逐题数据可直接读取，已逐项展开。旧 P7 A/B/C 使用相同 R01a–R06b，开发为 R01–R03，regression 为 R04–R06；原题均在第 09 文件中。

当前可直接核查的 [P7 历史阶段报告](history/v20261029_sqlite/internal_experiments/documentation/history/V03_P7.md)保存了分组指标和明确失败：R03b/C 恢复后仍 iteration_limit，R04a/C、R06b/C 耗尽轮次。该阶段文档指向的 `.test_runs/v03_p7/20261022_a/` 当前没有在本项目的保留运行目录中定位到对应逐题 report。本附录因此**没有将组均值复制给每道 P7 题，也没有把 Fusion 逐题分数冒充 P7**。这部分只能按现存阶段报告解释，不能声称已重新核对完整 36 条 P7 原始输出。

工程 121 项附的是当前保留测试源码中的断言和历史最终 XML，说明每个用例在检查什么；源码定位不等于重新执行所有回归。旧阶段 184/185 项、后续 111/37/121 项之间存在重叠，不将它们全加成独立测试能力分母。

手工编写的 RAG/Agent 集没有变成独立公共基准。公开 LongMemEval 的 oracle 也不是完整 LongMemEval-S。附录公开题目后，今后不能继续把它们称为新一轮未知盲测；若再做独立验证，应另建新集。现阶段不为补文档重新调用模型、改分或再调参。

## 5. 面试时如何准确表达

可以说：“我将评测分成检索证据定位、生成忠实性与覆盖、会话历史回忆、Agent 任务完成和确定性安全回归，各自有题源和对照。当前 RAG 题是源论文条件化银标，记忆使用公开 LongMemEval 单会话 oracle，Agent 是已曝光本地开发集。我保留逐题答案、评审和失败，而不是只展示均值。”

遇到追问时，按 **题源 → 实际问题 → 预期 → 各组结果 → 原文/日志依据 → 能证明什么/不能证明什么** 讲解。不要把 RAGAS 忠实性说成完全正确率，不把任务 partial 一律等同失败或成功，不把生成后的实验草案说成实验已完成。

本附录由只读抽取脚本 `self-revise/backend-revise/scripts/report_backend_questions.py` 从保留证据生成，手工入口用于解释口径。逐题文件及输入 SHA256 见 [生成清单](question-analysis-v20261110/manifest.json)。原问答、金银标、分数和业务代码不作修改。
