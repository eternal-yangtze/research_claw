## 3. 首次安装与启动（新机器或环境不存在时）

### 3.1 安装本机软件

安装 Docker Desktop（开启 Linux containers）、Python 3.12、Node.js 22 LTS 和 DBeaver Community。已有软件无需重复安装。PostgreSQL/Qdrant 由 Docker 提供，不需要本机 `psql`，数据库驱动由 DBeaver 或 Python 提供。

在 CMD 检查：

```cmd
python --version
node --version
npm.cmd --version
docker version
docker compose version
docker info --format "{{.OSType}}"
```

Docker 应同时显示 Client/Server，OSType 应为 `linux`。这些命令无需激活 Python 环境。

### 3.2 准备基础设施配置

使用仓库的 `infra/compose.yaml`；当前机器已准备好，不要重新覆盖。新机器需自行创建 `infra/.env`，只填写一项本地秘密：

```dotenv
POSTGRES_PASSWORD=替换为你自己设置的长密码
```

不要把占位符作为真实密码。`infra/.env` 供 Compose 初始化数据库使用；根目录 `.env` 和 `.env.web` 是应用配置，职责不同。秘密配置不提交 Git。

首次拉镜像、检查配置并启动：

```cmd
cd /d D:\my_coach\new_agent\ResearchClaw
docker compose --env-file infra\.env -f infra\compose.yaml config --quiet
docker compose --env-file infra\.env -f infra\compose.yaml pull
docker compose --env-file infra\.env -f infra\compose.yaml up -d
```

`config --quiet` 无输出表示语法检查成功；`pull` 下载固定镜像；`up -d` 创建或启动服务。配置检查失败时不要继续。不要使用会输出完整密码的普通 `config` 命令分享配置。

### 3.3 创建唯一 Python 环境并安装依赖

仅在 `.venv` 不存在时创建。所有本机 Python 运行均先激活再使用短命令：

```cmd
cd /d D:\my_coach\new_agent\ResearchClaw
python -m venv .venv
.venv\Scripts\activate
python -m pip install -r requirements.txt
python -m pip check
python -c "import sys; print(sys.executable)"
```

解释器应位于项目 `.venv\Scripts\python.exe`。安装依赖仅在首次准备或依赖清单变更时执行，不是每次启动都执行。依赖安装和 pip check 是否成功仍需实际验证，本次基础设施验收不包含这一项。

首次安装前端依赖：

```cmd
cd /d D:\my_coach\new_agent\ResearchClaw
npm.cmd --prefix frontend ci
```

该命令按 lockfile 重建 `frontend/node_modules`，不会装进 `.venv`，不需要激活 Python 环境。前端依赖变更或重建时才执行。

### 3.4 DBeaver 首次连接

数据库 → 新建数据库连接 → PostgreSQL。主机 `127.0.0.1`，端口 `5432`，数据库和用户名均为 `researchclaw`，密码使用 `infra/.env` 中对应值。首次下载 PostgreSQL JDBC 驱动后测试连接，连接名称建议 `ResearchClaw-本机Docker`。

SQL 编辑器执行：

```sql
SELECT current_database(), current_user, version();
```

当前用户已验证成功。后续直接打开保存的连接即可；没有业务表不代表连接失败。

## 6. 停止、重启和数据保护

先在应用终端 Ctrl+C 停止前后端，再停止数据库：

```cmd
docker compose --env-file infra\.env -f infra\compose.yaml stop
```

需要重启数据库时：

```cmd
docker compose --env-file infra\.env -f infra\compose.yaml restart postgres qdrant
```

停止和重启不会清空持久卷。不要使用 `down -v`、`docker volume rm` 或全局卷清理作为日常重启手段。源码目录改名不应导致重新建立数据库卷。DBeaver 删除连接也不等于删除数据库。

数据库初始化后，单独修改 `POSTGRES_PASSWORD` 环境变量不会修改已有数据库用户密码；密码变更应显式修改数据库用户并同步应用和 DBeaver，不能靠删卷解决。
