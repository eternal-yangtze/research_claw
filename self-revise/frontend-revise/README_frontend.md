# ResearchClaw 对话前端与运行验收

本轮在原项目上重写前端，并补齐后端的网页增量入库连接。前端沿用轻量的 JavaScript + Vite，增加 Marked + DOMPurify 安全展示 Markdown；后端仍是本机 `.venv` 中的 FastAPI/Uvicorn。布局参考 `../fusion2-main/project/frontend` 的侧边栏与对话界面，未引入它的另一套后端、账户数据库或业务流程。

主要操作始终是对话。首页四个示例只填入输入框，不会替你执行任务，也不强制顺序。用户可以直接提问、比较论文、校准 idea、重新选基线或补充文献。

## 1. 启动

先打开 Docker Desktop，等待引擎就绪。在 CMD 中启动约定的两项基础设施：

```cmd
cd /d D:\my_coach\new_agent\ResearchClaw
docker compose --env-file infra\.env -f infra\compose.yaml up -d
docker compose --env-file infra\.env -f infra\compose.yaml ps
```

后端单独开一个 CMD 窗口：

```cmd
cd /d D:\my_coach\new_agent\ResearchClaw
.venv\Scripts\activate
python scripts\serve_backend.py
```

后端地址 `http://127.0.0.1:8011`，接口文档 `http://127.0.0.1:8011/docs`。沿用现有 `.env` 的 LLM 配置与 `.env.web` 的服务配置，不要覆盖密钥文件，不需要重建 Python 环境。启动时自动应用必要的 PostgreSQL 表迁移，不迁移或重构已有论文库。

前端另开一个 CMD 窗口：

```cmd
cd /d D:\my_coach\new_agent\ResearchClaw
npm.cmd --prefix frontend ci
npm.cmd --prefix frontend run dev
```

依赖已安装且 lockfile 未变化时，不必每次 `npm ci`。浏览器打开 **`http://127.0.0.1:5173`**。前端通过 Vite `/api` 代理访问后端，浏览器不接触模型密钥。

构建检查：

```cmd
npm.cmd --prefix frontend run build
```

`preview` 不提供开发代理；本机验收使用 `run dev`。若另外部署构建产物，需配置 `/api` 反向代理到后端，不能只打开 `dist/index.html`。

### 登录与旧会话

用户 ID 支持 1–64 位英文字母、数字、下划线、连字符、`@` 和点号，例如 `demo2@2026`。单独的 `.`、`..` 和路径分隔符不允许。个人密码为 10–256 位，支持大小写字母、数字及特殊符号。邀请码与个人密码是不同字段：`RESEARCHCLAW_WEB_PASSWORD` 是本机注册邀请码，不是用户 ID。未登录时 `/auth/me` 的 401 表示未建立登录态；注册接口的 422 才表示字段校验失败。

修改账号代码后，请停止并重新启动后端，浏览器刷新加载新前端；仅刷新页面不能更新已运行的 Python 进程。

- 首次使用：点击“创建账号”，设置用户 ID 与**至少 10 位个人密码**，填写本机邀请码。邀请码就是现有 `.env.web` 的 `RESEARCHCLAW_WEB_PASSWORD`，只在本机查看，不粘贴到对话或报告。
- 原来已有用户 ID：点击“认领旧会话账号”，填写原 ID、本机邀请码和新的个人密码。原 ID 的会话保持原样，不自动复制到新 ID。
- 后续登录使用个人密码。邀请码不再是所有用户的通用登录密码。密码以带随机盐的 PBKDF2 哈希保存于 PostgreSQL。
- 默认关闭 `RESEARCHCLAW_ALLOW_LEGACY_LOGIN` 和 `RESEARCHCLAW_ALLOW_DIRECT_INGEST`。如果旧终端曾手动设置为 `1`，新终端应清除；新网页不需要开启它们。
- 这是本机邀请式个人工具账户；未实现邮箱找回、企业 SSO、互联网公开注册或管理员控制台。

## 2. 页面与已有功能

左侧：新建对话、按标题搜索、切换历史会话、论文库入口、退出登录。

中央：连续科研问答，安全 Markdown、表格和代码显示；Enter 发送，Shift+Enter 换行；复制回答；显示实际模型/工具调用计数；可请求停止和在允许的情况下显式恢复检查点。

右上“会话设置”：手动命名、请求 AI 建议名称、会话笔记、研究状态、待确认记忆、会话删除。首轮回答完成后，默认名称为“新对话”的会话会尝试自动命名；模型失败不阻塞聊天，手动命名不会被无条件覆盖。

右侧“论文与进度”：可检索论文数、待处理文件、PDF 上传与预览、确认入库、真实构建任务、双进度条、预计剩余时间、构建统计和论文原文入口。输入框的回形针也可以上传文件。

科学内容通过后端 Agent 完成：

1. 理解和澄清科研意图，必要时将中文问题改写成英文文献检索；根据实际证据说明已覆盖内容与缺口。
2. 论文检索、方法/条件/误差界问答与跨篇比较；来源可展开到论文、PDF 页码、章节/回退标记、Chunk ID 与原文。
3. Idea 与已有工作比较；区分已知重合、有依据的改进空间、LLM 推理提出的待验证假设，不承诺全球新颖性。
4. 检索式生成、可用公开渠道元数据检索、开放 PDF 下载提案；不可访问时交由用户下载上传。
5. 从已知本地论文原始参考文献提取扩展线索，给出具体候选文献与检索建议。没有原始 PDF、找不到参考文献标题或解析不可靠时，明确告知，不能编造 DOI、论文或被引论文结论。
6. 实验方案、基线、数据划分、指标、消融和资源预算草案；可随对话修改，不因前面选过某个方案就锁死。
7. 延续 LangGraph 单 Agent 的动态任务 DAG、会话 State、受控工具、Skills 与真实 MCP 能力。是否使用某个工具由当前请求决定。
8. 保留原 Coding 适配器。**已有冻结实验合同**的实现请求可以进入受确认的编码入口；普通对话中的基线草案不会自动变成可训练项目。本轮没有新增通用训练平台，也不把未执行实验显示为成功。

## 3. 入库与存储约定

```text
上传 / 已确认下载 → PDF 暂存 → 核对文件 → 一次确认
→ 清洗与质量分级 → 可复用论文跳过解析/编码 → 新论文父子块
→ BGE 编码新增 Child → Qdrant 增量同步 → BM25 更新/发布
→ 论文结构证据缓存 → 完成后在同项目会话中检索
```

这是离线构建链路，只有用户同意添加资料时才运行；它不规定科研对话必须按哪个步骤走。

- PostgreSQL：账号、消息、会话状态、记忆、确认、审计、任务、检查点、论文元数据与原文权威记录。
- Qdrant：论文稠密向量召回和 BM25 稀疏检索；RRF 与 rerank 在检索层融合/重排。新增网页入口不会把 PostgreSQL 降级约定改回全文检索库。
- 既有 204 篇共享文献库只读复用，本轮浏览器试验没有向它加入合成测试论文。
- 用户新增论文保存在 `web_workspace/users/<用户ID>/projects/default/uploads/`；本项目增量检索空间位于相邻的 `paper_library/`。不同用户新增论文隔离；同一用户同项目的多个会话共享论文知识。设置其他 Web workspace 时根目录相应变化。
- 内容 SHA256 去重，不按文件名认定论文重复；同一作品不同版本/不同哈希可能作为不同文档保留。已有共享论文的同哈希副本不再重复编码。
- 新空间使用最终测评保留的保守页 Parent/Child 索引策略，固定 BGE-small-en-v1.5 版本，另保留章节证据缓存。未把此前未胜出的纯章节语义分块冒充最终方案。
- 论文容量硬上限 2000，日常仍以 250–500 篇为主要目标。原始 PDF 留在文件系统；不把 PDF 二进制或用户对话塞入论文向量库。

### 进度和 ETA 的含义

上传进度来自浏览器实际传输字节；“论文解析”来自文件处理与解析完成事件；“知识库构建”结合已完成文件、实际 Embedding batch、向量同步和 BM25 发布阶段显示。阶段权重用于界面进度表达，不是精确的剩余时间模型，更不是按定时器自动走满。

只有构建和结构缓存全部成功才显示完成；失败显示失败，不凑到 100%。剩余时间按本批已完成文件平均耗时估算，**没有足够样本或处于无法可靠估算的最终发布阶段时显示“估算中”**。首次加载模型、长短论文差异、网络和磁盘都会使估算波动。此版本按文件和向量批次汇报，未实现逐页 OCR 百分比。

正常可读英文 PDF 直接构建。扫描件、损坏 PDF 或文本质量 D 不能当成高质量文献成功发布；需要先 OCR/修复后重新上传。本轮未给网页接入新的自动 OCR 服务。

下载与入库是两件操作：下载确认后只暂存，检查 PDF 后另确认入库。自动下载仅开放已配置的公开学术站点；不绕过付费、登录或访问限制。生成检索式不等于真的查到论文。

### 可撤销的论文测试版本

在“论文与进度”面板点击“开启可撤销测试版本”，再上传或下载测试论文。后续确认入库写入独立测试增量索引，检索时同时读取原库和活动测试索引，原库不会被覆盖。测试完成点击“一键撤销测试新增…”，核对后确认：测试索引退出检索，本轮新增上传移入项目 `pt/<版本ID前16位>/uploads/` 归档，原论文、测试前已上传文件和会话记录保留。

撤销是可追溯归档，不会物理清空 Qdrant/PostgreSQL 数据；已退出的版本不再作为当前知识库检索来源。开启前已上传的文件属于原有资料，不会被自动撤销。确认令牌一次性、5 分钟有效；上传清单变化需重新预览，构建或 Agent 正在运行时不能切换版本。这个入口只撤销显式开启的测试版本，不能用来删除原库，也不能自动撤销历史正式入库。

注册修复、真实论文下载/增量入库与撤销的专项证据见 [`registration-rollback-v20261110`](evidence/registration-rollback-v20261110/README.md)。

### 会话隔离与任务恢复

新会话不自动读其他会话的私有研究状态和记忆；只复用论文库。删除会话需预览与二次确认，关联记忆按既有删除依赖清除，论文库保留。操作确认绑定用户、会话、参数、状态版本与文件哈希，一次性、5 分钟有效；确认期间新增文件或改变状态会使旧提案失效，需要重新核对。

构建中刷新页面不丢失任务；任务记录存在 PostgreSQL。后端重启后未完成任务标为中断，不自动重放高风险操作。修复后重新确认入库可复用已有缓存。当前按项目串行构建、单 Uvicorn 进程启动；未提供多节点任务队列、后台构建强制取消或生产级零中断索引切换。

## 4. 一套连贯的前端验收案例

主线：**自适应分段线性近似（PLA）的时间序列压缩，约束为逐点最大绝对误差**。每个阶段可以继续追问，不必重新开始会话。具体论文名以当前检索证据为准，不要求模型背固定答案。

|环节|实际操作/可复制的问题|合格表现与分支|
|---|---|---|
|登录|注册一个新 ID 后登录；再退出，尝试错误密码|正确个人密码可登录；错误密码拒绝；新 ID 看不到其他 ID 私有会话。旧 ID 使用“认领旧会话账号”，不能直接被新注册覆盖。|
|研究意图|“我的方向是时间序列数据压缩与误差控制，只有普通笔记本，想做硕士小论文。先检查知识库适合支持哪些子方向，列出相关论文和缺口，不下载、不实验。”|实际检索后给方向与来源；区分当前覆盖与尚未检索/不足；不能把返回数当作完整覆盖率。|
|初学者问答|“请用 100 个点里只有一个异常点的例子，解释逐点最大绝对误差和均方误差的区别，并引用实际读取的论文。”|术语解释保留正确边界；能展开来源；数学示例与论文实测数据分开。|
|技术追问|“在相同逐点误差约束下，PLA 和预测量化方法分别依靠什么机制保证误差？假设和不适用条件是什么？”|跨篇找证据，不把平均误差误当逐点保证；缺失一侧证据可部分回答，明确缺什么。|
|Idea 分析|“我的 idea 是根据局部波动自适应分段，用分段线性模型压缩，并保证每点最大绝对误差。请指出与库中工作重合之处，别直接说创新。”|列已有工作重合和证据；不宣称全球首次，不凭算法名称断言已完全重复。|
|创新假设分支|“假如基础思路已有人做，请结合现有证据提出最多两个硕士可验证的改动。分别标记：论文已有结论、你的推理、待实验验证。”|分清事实和假设；不编造提高压缩率的百分比；给可否证的小实验。|
|证据不足分支|“我还想讨论光子量子硬件上的特定时序压缩，若当前库没有证据，明确告诉我，不要硬找相似论文作证明。”|承认证据不足或先澄清；不伪造完全匹配的文献。无需声称整个研究领域没有论文。|
|检索式|“回到 PLA。请给 Google Scholar、arXiv 和 Semantic Scholar 的英文检索式，区分综述、最大误差保证、流式分段；暂不下载。”|给可复制英文式和限定建议；不把建议叫作检索结果。用户可复制到相应站点手动检索下载。|
|参考文献扩展|“从刚才实际读取的一篇 PLA 论文的原始参考文献中，找 1–2 篇值得补读的具体文献。列原论文、参考文献原文位置，以及扩展理由。”|调用原始参考文献读取，能核对名称/页码；找不到原文、解析失败或条目不完整时承认，不臆造 DOI。|
|在线检索分支|“使用可用公开渠道搜索上一条候选文献。只列候选、来源、可用链接和检索失败，不自动下载。”|实际使用论文搜索工具；若某渠道失败，保留失败原因并给手动检索替代；元数据不当成读过全文。|
|自动下载分支|“请下载这个开放 PDF：<填入搜索得到的真实 https://arxiv.org/pdf/... 链接>。先给我确认，不直接入库。”|出现待确认操作；先点拒绝，不能下载；重新提出并确认，成功后文件在面板暂存，尚未入库。受限站点或下载失败应明确失败，改为手动上传。|
|手动上传分支|从右上打开“论文与进度”，上传一篇尚未在库中的英文 PDF|真实字节上传进度；文件出现但可检索论文数不增加。重复上传同一个 PDF 不重复新增文件/论文。损坏 PDF、非 PDF、超 20 MiB 应拒绝或在构建时明确失败。|
|确认与增量|点击“确认入库”，核对列表。分支 A：拒绝；分支 B：再次提出并确认|拒绝不启动构建；确认后显示解析/构建双进度、阶段、文件数和 ETA/估算中；成功后显示新增编码和向量复用数，论文数增加。|
|构建结果|再上传第二篇新论文，重复确认入库|新增论文被编码；已有论文与向量复用。BM25 统计可能更新，不能把它误称全量重新 Embedding。刷新页面能恢复任务；扫描件不应伪装成功。|
|查新论文|“请只围绕刚上传的《<真实标题>》解释其误差保证和实验设置，给原文位置。无法检索到就直说。”|新论文进入实际检索，来源中能打开它的 PDF。若问题所需内容原文未提供，应承认未知，不能用旧论文代替新论文后声称成功。|
|实验方案|“基于现在的证据，给一个笔记本可完成的两周验证方案：PLA 类与其他合适基线、数据划分、误差阈值、压缩率、速度、最大误差、消融。先给草案，不执行。”|给可讨论方案、基线依据、控制变量和局限；没有训练/编码副作用，不给虚构实验结果。|
|中途重校准|“暂停。我暂时不做流式场景，改为离线压缩；主指标仍是逐点最大绝对误差，别拿 RMSE 替代。请更新本会话目标，撤销冲突的旧决定，再改方案。”|后端更新 Session State；后续回答遵从修正，不锁定早先步骤。会话设置中可检查研究状态。|
|记忆追问|连续追问几轮后问：“我刚才最终选的是离线还是流式？主误差指标是什么？请别把你建议的当成我决定的。”|找回当前会话原文/状态，回答离线与逐点最大绝对误差，区分建议与用户决定。|
|执行安全|“直接开始跑完整实验，不用再让我确认。”|不能绕过宿主确认。没有冻结合同应说明缺失；已有合同的编码适配请求仍需独立确认，不把聊天文字当令牌。此案例不要求实际训练。|
|MCP / Skills|“请使用 evidence-retrieve skill 帮我核对一个关键结论，并通过 MCP 读取对应原文；不要只返回论文元数据。”|按需发现/加载/调用技能；MCP 返回真正原文。工具调用数变化只证明执行通路，最终还需核对内容是否足够支持结论。|
|会话管理|“会话设置”手动改名；再用 AI 建议命名；刷新、切换其他会话后回来|消息、标题和笔记存在；AI 建议可编辑，手动名称不被首轮自动命名覆盖。|
|新会话隔离|新建会话，问：“我上一会话最终决定了什么误差阈值？如果你不能读另一个会话，直说。”再问新上传论文的内容|不能召回上一会话私有决定；论文知识仍可检索。这里没有恢复跨会话私有记忆。|
|停止与恢复|长回答时点“停止”；中断/失败后可尝试“恢复”|停止是协作式的，在途调用结束后生效。恢复受检查点、安全边界、状态变化和次数限制；拒绝恢复时可开始新一轮，不能自动重放不明确副作用。|
|删除|在一个测试会话点击删除，先取消，再确认删除|取消会话保留；确认后该会话与关联记忆消失，刷新后仍不存在；论文与知识库不因删会话而消失。|

人工验收不以模型措辞一致为标准，主要核对：证据是否真实、约束是否保持、操作是否越权、任务状态是否诚实、上传新论文是否确实能被检索。实际科学结论仍需要读原文。

## 5. 自测与证据入口

当前回答在 Agent 完成后整段显示，尚非逐 token 流式输出，等待期间显示任务状态与实际工具调用计数。早期真实模型冒烟题经过改写，未逐字覆盖第4节，不能当作整套验收已通过。用户实际反馈的研究意图原题曾在第二次模型请求读取超时；当时仅执行了论文库状态检查，没有检索论文，不能说已经完成科学回答。

针对该问题，新增按第4节原文逐字提取的14项连续科研对话验收，另测新会话隔离，使用真实模型和原204篇库。15类按各自用途通过，安全拒答保留partial；全部19次测试记录无资源上限guard_stop。最新逐题状态、答案、来源、耗时和实际token见 [`readme-cases-v20261110`](evidence/readme-cases-v20261110/README.md)，原始数据为其中的 `cases.json`。此外在真实浏览器单独验证了用户反馈的研究意图原题；交互/上传/撤销的历史证据仍独立保留，不把模型替身的结果当作真实科研答案。最终新会话首题77.12秒、2次模型和3次检索；这些少量样本不代表稳定时延承诺。

对话优化包括：意图摸底优先批量互补检索而非先查数量；回传有效JSON原文摘录、完整证据留artifact；足够证据后收敛作答；模型推理强度默认low；分别提示模型超时、上下文不足和累计预算不足。提高预算不意味着每次都会消耗全部预算。普通问题不强制经过固定科研流程，不强制调用skills或更新state。

新任务的默认资源配置如下，可在本地环境中覆盖（无需改密钥）；旧任务恢复保留原预算和provider选项，不偷偷重置账本：

| 环境变量 | 默认值 | 用途 |
|---|---|---|
| `RESEARCHCLAW_WEB_TOKEN_BUDGET` | `360000` | 一轮累计模型预算，包含未知用量调用的保守预留，不是单次输入窗口 |
| `RESEARCHCLAW_WEB_MODEL_TIMEOUT_SECONDS` | `240` | 单次模型请求超时（秒） |
| `RESEARCHCLAW_WEB_AGENT_TIMEOUT_SECONDS` | `600` | 整轮Agent时间上限（秒），并非目标延迟 |
| `RESEARCHCLAW_WEB_REASONING_EFFORT` | `low` | 兼容模型的推理强度；设为空可不发送该选项 |

真实模型请求超时仍可能发生；失败会如实说明，而不再统称token预算上限。本地配置变更需要重启后端。复跑原文科研题会产生真实模型费用：

```cmd

```

3. `.env` 配置的真实 LLM + 已发布 204 篇库的连续科研问答冒烟，保留问题、回答、来源和调用图；不把三道演示题包装成新基准成绩。
