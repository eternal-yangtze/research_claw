# 应用性能与结果

ResearchOps 的结果围绕 Agent 应用链展开：检索取得合适证据，角色把证据组织为可用方案，Runtime 通过按需上下文和增量索引支撑持续使用。以下数字对应已有运行记录，按各自任务集合说明范围。

主要应用领域为小数据图像分类中的 ViT 参数高效微调。RAG 主对照固定 94 篇论文、7,757 段原文、6 个研究主题和 12 个问题。相关性、事实支持和方案评分采用 **LLM 银标**；语义评价以同轮固定规则的匿名评审为依据。

## 数据集与实际运行规模

论文问题集用于衡量检索与证据组织，研究任务集用于衡量合同交付，图像数据用于 Coding 的数据交接和实际代码执行。各自规模如下：

| 应用环节 | 数据集或任务集合 | 规模与实际使用范围 |
| --- | --- | --- |
| 文献检索与证据支撑 | 自建 ViT 参数高效微调论文语料与问题集 | 94 篇论文、7,757 段原文、6 个研究主题、12 个问题；新增论文子集为 7 篇 |
| 增量索引维护 | 同一论文语料的扩库过程 | 87 篇扩至 94 篇，复用 7,227 段、新增 530 段 |
| Coding 前研究方案交付 | 6 个同领域新组合任务 | 5 个任务要求 DTD / Oxford-IIIT Pet，1 个要求 CIFAR-100 / Flowers-102；以正式研究合同和冻结规格为交付终点 |
| 联合 Coding 案例的数据交接 | DTD、Oxford-IIIT Pet | DTD 为 47 类、原始清单 5,640 张；Pet 为 37 类、本地准备清单 7,349 张，数据清单随合同交接 |
| 联合 Coding 案例的实际执行 | DTD / Pet 真实图像小批量 | CPU tiny-ViT、32 × 32 输入、batch size 2，完成第 2 步到第 3 步的续训；合同包含 36 项计划任务，用于研究配置与调度交接 |

上述图像规模采用实际交接清单口径。DTD 去除跨划分像素重复后，有效 train / val / test 为 1,874 / 1,874 / 1,880 张；Pet 本地准备清单的划分为 3,315 / 365 / 3,669 张。清单大小描述可用资料范围，实际训练规模以所列小批量和步数为准；完整预训练模型、多随机种子研究属于后续研究执行范围。检索指标的统计单位是论文问题集，方案交付率的统计单位是研究任务。

## 检索融合与原文支撑

融合路径保留原有候选，以多查询召回和来源约束排序组织论文与段落。论文排名按片段首次出现去重，取前十后按问题宏平均。

| 指标 | 旧完整链路 | Fusion 完整链路 |
| --- | ---: | ---: |
| nDCG@10 | 0.690 | **0.749** |
| Recall@10 | 42.21% | **42.89%** |
| 新增 7 篇论文 Recall@10 | 43.75% | **50.69%** |
| 全部输出事实获原文充分支持 | 75.51% | **96.15%** |
| 方案可用性，0–4 分 | 2.42 | **4.00** |
| 实验设计六维均分，0–4 分 | 2.21 | **3.82** |

检索指标描述论文排序；原文支持率以全部输出事实为分母；方案评分描述完整生成链路。Fusion 的证据卡、研究蓝图与修订共同参与生成，整条链的方案收益与单个向量后端的作用分别解释。

## 查询规划与证据组织

在相同语料上，完整神经 RAG 配合面向研究目标的查询规划，论文 Recall@10 从原始问题的 **27.62% 提高到 42.21%**，nDCG@10 从 **0.519 提高到 0.690**。

另一组固定语料的组件对照表明，检索之后的证据组织具有直接应用价值：

| 指标 | 只改检索 | 检索 + 证据卡 + 蓝图 + 修订 |
| --- | ---: | ---: |
| 方案可用性，0–4 分 | 2.75 | **4.00** |
| 实验设计均分，0–4 分 | 2.47 | **3.85** |
| 事实支持率 | 66.67% | **74.42%** |

这组观察支持将 RAG 的输出从“相关文本集合”继续组织为方法、约束、对照和原文引用，再交给规划与评审角色。

## Skills 与上下文效率

按需加载让模型先阅读能力元信息，再加载适用 Skill 的正文。两个完成运行的 lazy / eager 重复对照结果为：

| 度量 | 按需加载 | 全量加载 |
| --- | ---: | ---: |
| 初始提示 token | **881** | 2,817 |
| 重复一的总 token | **4,517** | 10,698 |
| 重复二的总 token | **4,604** | 10,700 |

初始提示减少 **68.7%**，两次总量的平均减少 **57.4%**。这些数字度量相同任务下的上下文加载方式，范围为所列两个完成运行；Skills 的调用路径仍保留工具授权和版本绑定。

统计采用上述两次完成任务的上下文汇总，初始提示和总 token 分别比较。

## 增量知识库维护

知识库由 87 篇扩展到 94 篇时，复用已有 7,227 段向量，三批新增 530 段。向量缓存同时关联内容 hash、模型与 revision。

| 项目 | 同轮单机观测 |
| --- | ---: |
| 旧向量复用率 | **93.2%** |
| 530 段增量编码 | **21.92 秒** |
| 7,757 段全量重建 | 278.83 秒 |
| 增量编码相对全量重建 | 约 **12.7 倍**加速 |

这些耗时针对编码与索引维护，适用于所列单机配置。Qdrant 为 Runtime 提供独立向量服务、范围过滤、版本化索引与持久化能力；神经语义质量由 Embedding、查询规划、召回与重排共同形成。

## Coding 前端到端

端到端终点定义为：自然语言研究目标经过文献取证、方案生成、宿主编译和独立评审，输出可交接 Coding 的冻结规格。

| 任务集合 | 最终交付结果 |
| --- | ---: |
| 6 个同领域新组合研究任务 | **83.3%（5/6）** |
| 同一组 6 题修复复验，复用获取 checkpoint | **100%（6/6）** |
| 4 个参数或指标表达变体 | **100%（4/4）** |

新组合任务与同题复验分别列出。修复复验属于已暴露题目的组件改进，终点是研究规格交付。正式训练收益由后续实际训练衡量。

联合业务案例进一步把 Qdrant 神经检索、MCP 论文回读、LangGraph 角色组和 Coding 串联：论文分析工件进入方案上下文，正式合同交接 36 项计划任务，Coding 完成 6 个模块并产生 Docker 执行报告。实际执行使用 DTD / Pet 真实图像小批量、CPU tiny-ViT、32 × 32 输入和 batch size 2，完成第 2 步到第 3 步的续训，展示任务交接、代码实现与状态续接能力。36 项计划任务描述研究设计与调度规模，完整多随机种子训练留给研究执行环节。

## 指标与可解释性

- 检索排名使用 Recall、MRR 和 nDCG；论文级与段落级分母分别维护。
- 引用回到原文位置，语义支持判断使用独立模型调用；事实支持与引用位置分别记录。
- 方案交付关注约束、数据隔离、合同与评审结果；训练指标由执行阶段产生。
- RAGAS 接收实际问题、答复和已暴露上下文，参考来源和银标身份随样本保存。

当前结果采用固定语料、小规模任务和模型银标，面向组件选择与应用实现。任务分层与后续研究投入的选择见 [README 的设计取舍](../README.md#关键设计与决策取舍)。

RAGAS 的接口结构、指标输入和安装方式见 [EVALUATION.md](EVALUATION.md)。以上表格保留应用指标、样本范围与统计口径，便于按相同定义在自己的知识库和任务上度量。
