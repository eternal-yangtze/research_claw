# 科研性能评测

本报告汇总 coding 前端到端、检索、生成、消融、增量索引、局部性能和 token 成本。数字来自已保存的实验记录，逐题结果见 [Precode 明细](../evaluation/results/precoding_v4_metrics.json)、[增量 RAG 明细](../evaluation/results/rag_incremental_metrics.json) 和 [完整实测报告](../evaluation/results/measured_reports.json)。

## 评测方法论

### Oracle 与评测终点

任务的 oracle 决定评测范式。具有可执行测试的任务可以约定采样预算并统计 pass@k。科研方案涉及问题契合度、对照公平性和证据解释，评委判断会影响得分。本项目为这类任务采用固定评委配置下的对照、组件消融和可计数 grounding，科研方案不设置 pass@k 基线。

评测终点分为检索排序、证据答复质量和 coding 前规格交付。端到端交付要求机械 Gate、科学性评审和独立终审满足条件，适用批次还要求累计 token 在预算内。计划中的训练操作为冻结规格；训练收益与研究假设需要实验结果验证。

主要领域为小数据图像分类中的 ViT 参数高效微调。RAG 主对照固定 6 个 IDEA、12 个问题、94 篇论文和 7,757 个段落。扩库实验使用同一批原始论文的四个快照，分母在各表就近说明。

### 三类证据

**对照**比较同一问题、语料和评委配置下的方法表现。检索对照使用 BM25、向量、混合和完整神经 RAG；Fusion 阶段比较旧完整方案、CPU 方案和 Fusion 方案。生成对照统一原始问题、输出格式和证据字符上限，完整方法增加的内部调用单独记入成本。

**消融**拆分组件贡献。查询规划实验分别比较原始问题与规划查询；生成实验比较无 RAG、关键词 RAG 和完整神经 RAG；CPU 组件实验比较旧流程、只改检索，以及检索加证据卡、蓝图和修订。单轮组件消融使用同一评委重新评分。

**Grounding**同时记录引用位置和语义支持。程序核对 chunk 身份、来源、原文位置及连续引文；LLM 银标逐条核对事实与所引原文的支持关系。论文相关性标签覆盖固定语料的全文提取文本，等级为 0–2；有效正标签需要原文节点与可核对引文。片段相关性评审覆盖候选池，片段召回以候选池内的相关片段为分母。

论文 Recall@10、MRR@10 和 nDCG@10 按问题宏平均，论文排名按片段首次出现去重后取前十。事实充分支持率以全部输出事实为分母；充分支持的已引用事实以已引用事实为分母；引用定位率统计引用能否回到原文。三个指标分别报告。

### 评委托管与公平性三固定

相关性标签、评测规则和期望约束由评测代码持有。检索器、查询规划器和生成器接收任务与证据，标签仅供评测器计算指标。模型请求、响应、方法别名映射、输入 hash 和调用账本随实验保存。

- **固定输入**：同一对照轮次使用相同问题、语料快照和标签。CPU 与 Fusion 生成对照统一最终输出格式、2,400 输出 token 上限、900 中文字符要求及 10,000 来源字符上限。完整方法的内部调用另计。
- **固定评委**：同一轮次使用相同模型配置和 rubric。CPU、Fusion 阶段将候选答案匿名化、随机排列后放入同一次评审调用；裁判只按答案对应的来源核对引用支持。生成器与裁判采用同模型的独立调用。
- **固定计算规则**：提前保存协议、指标、分母和接受条件。零相关论文的查询指标记为 `null`；失败请求与未知 usage 保留成本；各轮分别报告原始结果、修订结果和缓存复用。

查询规划 v2 对逐字相同的无检索请求统一复用 v1 缓存，带检索答案根据新证据生成，全部匿名答案重新一起评审。Fusion 阶段复用已固定的旧方案和 CPU 答案，与新 Fusion 答案在同一次匿名调用中评分。复用请求以 SHA-256 留档，原始生成成本保留在来源阶段。

### 解释边界与人工金标

相关性、方案分和事实支持判定均采用 LLM 银标，非人工金标。同模型的独立调用存在相关偏差，匿名顺序控制保留评委本身的偏好和波动。固定语料单轮对照支持本轮相对改进的描述；完整方法增加的模型调用计入费用。

CPU、Fusion 与 v4.1 使用已暴露任务进行组件改进或修复复验。检索的全球召回、长期扩库行为、负载吞吐、独立公式识别正确率和训练收益各有独立的评测范围。本报告数字覆盖固定语料、所列问题和已有单机观测。

描述区间按 6 个 IDEA 聚类进行配对 bootstrap，95% 区间用于展示小样本不确定性。Recall 和 nDCG 的部分增量区间跨零，结果按原值保留。

人工金标评测可采用领域专家独立标注、分歧裁决和专家间一致性统计，并保留与 LLM 银标的逐题差异。该设计需配套独立题目与原文证据，当前报告的评分来源为 LLM 银标。

## Token 账本

本表验证的架构决策是：调用前预留预算，响应后结算已知 usage，失败或中断保留未知用量预留。

数据来源：各行沿用对应阶段账本；历史累计与子组件存在包含关系，阶段总量分别报告。
